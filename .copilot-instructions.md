# GitHub Copilot Instructions for ProStore

## Project Overview
This is a full-stack e-commerce application built with Next.js 14, TypeScript, Prisma ORM, and NextAuth.js.

## Key Guidelines

### 1. Folder Structure
- **Do NOT modify or restructure the existing folder organization**
- Maintain the current directory hierarchy:
  - `app/` - Next.js App Router structure with nested layouts
  - `components/` - Reusable UI and feature components
  - `lib/` - Utilities, validators, and server actions
  - `db/` - Database configuration and seeding
  - `prisma/` - Prisma schema and migrations
  - `types/` - TypeScript type definitions
  - `public/` - Static assets
- Add new files within existing folders, do not create new top-level directories

### 2. Technology Stack - No Changes
- **Do NOT add new libraries or dependencies** to the project
- **Do NOT introduce new tech stacks or frameworks**
- Work within the current ecosystem:
  - **Framework**: Next.js 14 with App Router
  - **Language**: TypeScript
  - **Database**: PostgreSQL with Prisma ORM
  - **Authentication**: NextAuth.js
  - **UI Components**: Shadcn/Radix UI
  - **Styling**: Tailwind CSS
  - **Forms**: React Hook Form + Zod validation
  - **Payment**: PayPal and Stripe integrations
  - **File Upload**: Uploadthing
  - **Testing**: Jest
  - **Email**: React Email components

### 3. Code Standards
- Follow existing code patterns and conventions throughout the codebase
- Use TypeScript strict mode
- Implement proper error handling and logging
- Create server actions in `lib/actions/` for mutations
- Use Zod validators in `lib/validators.ts` for all inputs
- Follow the component structure: UI components in `components/ui/`, feature components in `components/`

### 4. Database Changes
- Any schema modifications must use Prisma migrations
- Update `prisma/schema.prisma` appropriately
- Do NOT directly modify database without migrations

### 5. Authentication & Authorization
- Respect the existing NextAuth.js configuration
- Use `requireAdmin` guard from `lib/auth-guard.ts` for admin routes
- Maintain role-based access control patterns

### 6. When in Doubt
- Reference existing similar implementations in the codebase
- Follow the established patterns for new features
- Maintain consistency with the current architecture
